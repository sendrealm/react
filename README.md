# Sendrealm React SDK

React SDK for Sendrealm web push integrations.

## Setup

Install the package:

```bash
npm install @sendrealm/react
```

Install the same-origin service worker file:

```bash
npx @sendrealm/react setup
```

The setup command detects your public directory and writes
`sendrealm-service-worker.js` there. Re-run it after SDK upgrades to refresh the
worker.

Browsers require service workers to be served from your app origin. Do not
register a GitHub or CDN URL directly as the service worker script.

## Browser support

The SDK uses the standard Notifications, Push, and Service Worker APIs and is
designed for current Chrome, Edge, Brave, Firefox, and Safari releases.

- Production sites must use HTTPS. `localhost` is supported for local testing.
- Ask for permission from a user action such as a button click.
- On iPhone and iPad (iOS/iPadOS 16.4 or later), users must first install the
  web app on the Home Screen and open it there before enabling notifications.
- The same-origin service worker generated by the setup command must remain
  reachable at the configured path.

## Migrating from another push provider

Two push SDKs must not register different workers at the same scope. For a
temporary production migration, keep the existing provider on its current
scope and install Sendrealm on an isolated path and scope:

```bash
npx @sendrealm/react setup \
  --path /push/sendrealm/sendrealm-service-worker.js
```

```ts
await init({
  appId: 'YOUR_SENDREALM_PUSH_APP_ID',
  autoRequestPermission: false,
  serviceWorkerPath: '/push/sendrealm/sendrealm-service-worker.js',
  serviceWorkerScope: '/push/sendrealm/'
});
```

The SDK ignores broader-scope registrations when using an isolated scope, so it
does not reuse or unsubscribe another provider's subscription. It also refuses to
replace a different worker at the configured scope unless
`allowServiceWorkerReplacement: true` is set explicitly.

Browser push subscriptions cannot be imported between providers because they
are tied to the provider's VAPID key. Users who already granted notification
permission can create the Sendrealm subscription without another browser
permission prompt when they revisit the site. Run both providers only during a
controlled migration, validate Sendrealm delivery, then remove the previous SDK
and worker according to your cutover plan.
